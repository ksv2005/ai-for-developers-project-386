# Хранить данные в памяти за интерфейсом репозитория

Для учебного проекта данные (Типы событий, Бронирования) живут в памяти процесса; потеря при перезапуске допустима. Доступ идёт через интерфейс репозитория, чтобы позже заменить хранилище на SQLite без изменения остального кода. Рассматривались SQLite-файл и Postgres: отвергнуты как избыточные на старте.

Проверка пересечения и запись Бронирования — одна операция репозитория (`createIfFree`), а не два вызова из сервиса: в памяти она атомарна, а при переходе на SQLite станет транзакцией, и гарантия останется на том же месте.
